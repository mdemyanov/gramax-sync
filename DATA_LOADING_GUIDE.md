# Инструкция по загрузке данных в локальную папку

## Обзор процесса

Процесс загрузки данных состоит из трёх основных шагов:
1. **Первоначальная настройка** (`init`) - создание конфигурации проекта
2. **Аутентификация** (`auth login`) - получение доступа к GitLab
3. **Клонирование репозиториев** (`clone`) - загрузка репозиториев в локальную папку

---

## Шаг 1: Первоначальная настройка

### 1.1. Запуск команды init

```bash
# Интерактивная настройка (рекомендуется)
gramax-sync init

# Или с параметрами
gramax-sync init \
  --repo-url https://itsmf.gitlab.yandexcloud.net/ritm-authors/gramax-yaml-manager \
  --branch master \
  --catalog-branch private
```

### 1.2. Что происходит при init

1. **Подключение к репозиторию конфигураций**
   - По умолчанию: `https://itsmf.gitlab.yandexcloud.net/ritm-authors/gramax-yaml-manager`
   - Ветка: `master` (для конфигураций)

2. **Проверка доступа**
   - Если токен не найден, будет предложена аутентификация
   - Проверяется наличие файла `workspace.yaml` в репозитории

3. **Загрузка структуры проекта**
   - Загружается `workspace.yaml` с описанием всех секций и каталогов
   - Отображается структура проекта

4. **Интерактивный выбор**
   - Выбор режима: по секциям или по каталогам
   - Выбор конкретных секций/каталогов для работы

5. **Сохранение конфигурации**
   - Конфигурация сохраняется в `~/.config/gramax-sync/config.yaml`
   - Указывается `workspace_dir` - папка для загрузки репозиториев

### 1.3. Пример интерактивного выбора

```
Выберите режим выбора:
  1. По секциям (выбрать целые секции)
  2. По каталогам (выбрать отдельные каталоги)

Выберите режим [1]: 1

Доступные секции:
  1. 1-методология
  2. 2-инфраструктура
  3. 3-приложения

Выберите секции (через запятую) [все]: 1,2
```

### 1.4. Результат init

После успешного выполнения `init`:
- ✅ Создана конфигурация в `~/.config/gramax-sync/config.yaml`
- ✅ Указана папка для workspace (например, `~/gramax-workspace`)
- ✅ Выбраны секции/каталоги для работы

**Важно:** Если аутентификация не была выполнена, перейдите к шагу 2.

## Шаг 2: Аутентификация (если не выполнена)

### 2.1. OAuth аутентификация (рекомендуется)

```bash
# Базовый вариант
gramax-sync auth login --oauth --url https://itsmf.gitlab.yandexcloud.net

# С указанием Application ID
gramax-sync auth login --oauth \
  --url https://itsmf.gitlab.yandexcloud.net \
  --application-id "ваш_application_id"
```

**Что происходит:**
1. Открывается браузер с страницей авторизации GitLab
2. После авторизации токен сохраняется в keyring
3. Токен используется для доступа к репозиториям

**Подробнее:** См. [MANUAL_OAUTH_TESTING.md](MANUAL_OAUTH_TESTING.md)

### 2.2. Personal Access Token (альтернатива)

```bash
gramax-sync auth login --pat --url https://itsmf.gitlab.yandexcloud.net
```

Будет запрошен токен в интерактивном режиме.

### 2.3. Проверка аутентификации

```bash
# Проверить статус токена
gramax-sync auth status --url https://itsmf.gitlab.yandexcloud.net

# Проверить валидность токена через API
gramax-sync auth status --url https://itsmf.gitlab.yandexcloud.net --check-validity
```

## Шаг 3: Клонирование репозиториев

### 3.1. Базовое клонирование

```bash
# Клонировать все репозитории из конфигурации
gramax-sync clone
```

**Что происходит:**
1. Загружается конфигурация из `~/.config/gramax-sync/config.yaml`
2. Создаётся структура папок: `{workspace_dir}/{section}/{catalog}/`
3. Клонируются репозитории в соответствующие папки
4. Используется ветка `private` (или указанная в конфигурации)

### 3.2. Структура создаваемых папок

```
{workspace_dir}/
├── 1-методология/
│   ├── ritm-methodology/
│   │   └── [содержимое репозитория]
│   └── ritm-docs/
│       └── [содержимое репозитория]
├── 2-инфраструктура/
│   └── ritm-infra/
│       └── [содержимое репозитория]
└── ...
```

### 3.3. Фильтрация при клонировании

```bash
# Клонировать только определённые секции
gramax-sync clone --section "1-*"

# Клонировать только определённые каталоги
gramax-sync clone --catalog "ritm-*"

# Комбинация фильтров
gramax-sync clone --section "1-методология" --catalog "ritm-methodology"
```

**Примеры фильтров:**
- `--section "1-*"` - все секции, начинающиеся с "1-"
- `--catalog "ritm-*"` - все каталоги, начинающиеся с "ritm-"
- `--section "1-методология"` - конкретная секция

### 3.4. Что происходит при клонировании

1. **Проверка существования**
   - Если репозиторий уже существует (есть папка с `.git`), он пропускается
   - Выводится сообщение: `⏭️  {section}/{catalog} уже существует`

2. **Создание структуры папок**
   - Автоматически создаются все необходимые папки
   - Если папка существует, она не перезаписывается

3. **Клонирование репозитория**
   - URL формируется как: `{base_url}/ritm-authors/{catalog_name}`
   - Клонируется ветка `private` (или указанная в конфигурации)
   - Используется shallow clone (`depth=1`) для экономии места

4. **Обработка ошибок**
   - Если ветка не найдена, пробует клонировать `main`/`master`
   - Если репозиторий недоступен, выводится ошибка и процесс продолжается

### 3.5. Пример вывода

```
📦 Клонирование 5 репозиториев...
⠋ Клонирование 1-методология/ritm-methodology...
✅ 1-методология/ritm-methodology клонирован
⠋ Клонирование 1-методология/ritm-docs...
✅ 1-методология/ritm-docs клонирован
⏭️  2-инфраструктура/ritm-infra уже существует
⠋ Клонирование 2-инфраструктура/ritm-tools...
✅ 2-инфраструктура/ritm-tools клонирован

✅ Успешно: 3
⏭️  Пропущено: 1
❌ Ошибок: 1
```

## Проверка результата

### 4.1. Проверка структуры папок

```bash
# Перейти в workspace директорию
cd ~/gramax-workspace  # или указанная в конфигурации

# Просмотреть структуру
tree -L 2  # или ls -R
```

### 4.2. Проверка статуса репозиториев

```bash
# Проверить статус всех репозиториев
gramax-sync status

# Проверить статус конкретной секции
gramax-sync status --section "1-методология"
```

### 4.3. Проверка конфигурации

```bash
# Просмотреть текущую конфигурацию
gramax-sync edit show

# Проверить путь к workspace
cat ~/.config/gramax-sync/config.yaml | grep workspace_dir
```

## Управление конфигурацией

### 5.1. Добавление новых репозиториев

```bash
# Добавить секцию/каталог в конфигурацию
gramax-sync edit add --section "1-методология" --catalog "ritm-new-repo"

# Или интерактивно
gramax-sync edit add
```

После добавления выполните `gramax-sync clone` для клонирования нового репозитория.

### 5.2. Обновление конфигурации с сервера

```bash
# Обновить конфигурацию с сервера
gramax-sync update
```

Это загрузит актуальную версию `workspace.yaml` с сервера и обновит локальную конфигурацию.

### 5.3. Удаление репозиториев из конфигурации

```bash
# Удалить секцию/каталог из конфигурации
gramax-sync edit remove --section "1-методология" --catalog "ritm-old-repo"
```

**Важно:** Это удаляет только из конфигурации, но не удаляет папки с диска.

## Решение проблем

### Проблема: "Конфигурация не найдена"

**Решение:**
```bash
# Выполните первоначальную настройку
gramax-sync init
```

### Проблема: "Не удалось клонировать репозиторий"

**Возможные причины:**
1. Нет доступа к репозиторию - проверьте права доступа в GitLab
2. Неверный токен - выполните `gramax-sync auth login` заново
3. Репозиторий не существует - проверьте название каталога

**Решение:**
```bash
# Проверить аутентификацию
gramax-sync auth status --check-validity

# Повторная аутентификация
gramax-sync auth login --oauth
```

### Проблема: "Порт занят" при OAuth

**Решение:**
- Система автоматически найдёт свободный порт
- Или освободите порт 8765: `lsof -i :8765` и `kill <PID>`

### Проблема: Репозиторий уже существует, но нужно переклонировать

**Решение:**
```bash
# Удалите папку репозитория вручную
rm -rf ~/gramax-workspace/1-методология/ritm-methodology

# Затем выполните clone
gramax-sync clone
```

### Проблема: Неверная ветка

**Решение:**
- По умолчанию используется ветка `private`
- Если ветка не найдена, система попробует клонировать `main`/`master`
- Проверьте наличие ветки в репозитории GitLab

## Рекомендации

1. **Первый запуск:**
   ```bash
   # 1. Настройка
   gramax-sync init
   
   # 2. Аутентификация (если не выполнена в init)
   gramax-sync auth login --oauth
   
   # 3. Клонирование
   gramax-sync clone
   ```

2. **Регулярное обновление:**
   ```bash
   # Обновить конфигурацию
   gramax-sync update
   
   # Обновить репозитории
   gramax-sync pull
   ```

3. **Работа с конкретными секциями:**
   ```bash
   # Клонировать только нужные секции
   gramax-sync clone --section "1-методология"
   
   # Работать только с этими секциями
   gramax-sync status --section "1-методология"
   gramax-sync commit --section "1-методология"
   ```

4. **Организация workspace:**
   - Используйте отдельную папку для workspace (не в проекте gramax-sync)
   - Рекомендуется: `~/gramax-workspace` или `~/Projects/gramax-workspace`
   - Регулярно делайте резервные копии важных изменений
